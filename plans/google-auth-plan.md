# Google Authentication for Expo SDK 50

## Recommended Architecture

The Expo application is a public OAuth client of this identity server. Google is an upstream OpenID Connect provider used only by the identity server.

```text
Expo app -> Identity server authorization endpoint
         -> Google OIDC authorization
         -> Identity server Google callback
         -> Identity server authorization code
         -> Expo app token exchange
```

The Expo app must never contain the Google client secret and must never send Google access or ID tokens to your APIs. Your APIs should trust only tokens issued by this identity server.

```
Issuer:
https://identity-server-00186add9672.herokuapp.com

Client ID: client_IKOuCaC-QT2cM8DmF2IroxFe

Redirect URI:
relationshipapp://oauth/callback

Scopes:
openid profile email offline_access orders.read

{
  "client_id": "client_IKOuCaC-QT2cM8DmF2IroxFe",
  "client_name": "Production - Relationship App",
  "grant_types": [
    "authorization_code",
    "refresh_token"
  ],
  "redirect_uris": [
    "relationshipapp://oauth/callback"
  ],
  "post_logout_redirect_uris": [
    "relationshipapp://oauth/callback"
  ]
}

```

The client must also be allowed to request `openid`, `profile`, `email`,
`offline_access`, and `orders.read`. The authorization response must grant
`offline_access`; otherwise the token endpoint will omit `refresh_token` and
the app will need to sign in again when the access token expires.

Register the exact post-logout URI used by each platform. Native development
uses `relationshipapp://oauth/callback` by default. Web development uses the
platform callback generated by Expo, usually
`http://localhost:8081/oauth/callback`; set
`EXPO_PUBLIC_OAUTH_POST_LOGOUT_REDIRECT_URI` when an explicit value is needed.

## Expo SDK 50 Dependencies

From the Expo app directory:

```bash
npx expo install expo-auth-session expo-web-browser expo-secure-store
```

Do not use an embedded WebView for authentication. `expo-auth-session` uses the system browser flow supported by iOS and Android.

Add a custom scheme to `app.json` or `app.config.js`:

```json
{
  "expo": {
    "scheme": "myapp",
    "ios": {
      "bundleIdentifier": "com.example.myapp"
    },
    "android": {
      "package": "com.example.myapp"
    }
  }
}
```

Use a development build or production build when testing native redirects. Expo Go uses a proxy redirect model and is not representative of a production standalone app.

## Expo Authorization Code + PKCE Flow

Use the identity server’s discovery document, not Google’s discovery document:

```tsx
import * as AuthSession from 'expo-auth-session';
import * as SecureStore from 'expo-secure-store';
import * as WebBrowser from 'expo-web-browser';
import { useEffect } from 'react';

WebBrowser.maybeCompleteAuthSession();

const issuer = 'https://identity.example.com';
const clientId = 'client_from_identity_server_admin_api';

export function useIdentityLogin() {
  const discovery = AuthSession.useAutoDiscovery(issuer);
  const redirectUri = AuthSession.makeRedirectUri({
    scheme: 'myapp',
    path: 'oauth/callback'
  });

  const [request, response, promptAsync] = AuthSession.useAuthRequest(
    {
      clientId,
      redirectUri,
      responseType: AuthSession.ResponseType.Code,
      scopes: ['openid', 'profile', 'email', 'offline_access', 'orders.read'],
      usePKCE: true,
      extraParams: {
        // Generate and persist a cryptographically random nonce for the login attempt.
        // Keep the nonce associated with this request until the callback is handled.
        nonce: 'random-nonce-created-for-this-request'
      }
    },
    discovery
  );

  useEffect(() => {
    if (response?.type !== 'success' || !request || !discovery) return;

    const code = response.params.code;
    const codeVerifier = request.codeVerifier;
    if (!code || !codeVerifier) return;

    void exchangeCode({
      code,
      codeVerifier,
      redirectUri,
      tokenEndpoint: discovery.tokenEndpoint
    });
  }, [response, request, discovery, redirectUri]);

  return {
    ready: Boolean(request && discovery),
    signIn: () => promptAsync({ useProxy: false })
  };
}

async function exchangeCode(input: {
  code: string;
  codeVerifier: string;
  redirectUri: string;
  tokenEndpoint?: string;
}) {
  if (!input.tokenEndpoint) throw new Error('Identity server discovery is incomplete');

  const body = new URLSearchParams({
    grant_type: 'authorization_code',
    client_id: clientId,
    redirect_uri: input.redirectUri,
    code: input.code,
    code_verifier: input.codeVerifier
  });

  const response = await fetch(input.tokenEndpoint, {
    method: 'POST',
    headers: { 'content-type': 'application/x-www-form-urlencoded' },
    body
  });

  if (!response.ok) throw new Error('Identity server token exchange failed');

  const tokens = await response.json() as {
    access_token: string;
    refresh_token?: string;
    expires_in?: number;
    token_type: string;
  };

  await SecureStore.setItemAsync('identity.refresh_token', tokens.refresh_token ?? '');
  // Keep the access token in memory. Do not persist it in AsyncStorage.
  return tokens;
}
```

Replace the example nonce with a cryptographically random value generated per authorization request. Do not reuse a nonce across logins. Keep the request and nonce together until the callback succeeds or expires.

The `useProxy: false` setting is for a development build or production native build using the app’s registered redirect URI. Expo Go may require the Expo AuthSession proxy during local experimentation; if you use it, register the proxy redirect URI separately and do not ship that configuration as production behavior.

## Refresh Tokens

Use refresh-token rotation from the identity server:

1. Keep the refresh token in `expo-secure-store`.
2. Keep the access token in memory.
3. Send the refresh token to the identity server token endpoint when the access token expires.
4. Replace the stored refresh token with the rotated value on every successful refresh.
5. If refresh-token reuse or invalidation is reported, delete the stored token and require a new browser login.
6. Revoke the refresh token at logout when possible, then delete it locally.

Never put access tokens or refresh tokens in URLs, logs, analytics events, crash reports, or ordinary persistent storage.

## Logout

At minimum, the Expo app should:

```ts
await SecureStore.deleteItemAsync('identity.refresh_token');
```

For server-side revocation, POST the refresh token to the identity server’s revocation endpoint before deleting the local copy. Clear local application state after the request completes or times out.

If browser single-sign-on logout is required, add an explicit OIDC RP-initiated logout flow later. Do not invent a logout URL or treat deleting the local token as global provider logout.

## Redirect and Build Checklist

- The issuer is HTTPS outside local development.
- The Expo redirect URI exactly matches the registered identity-server client URI.
- The Google redirect URI points only to the identity server callback, never to the Expo app.
- The Google client secret exists only in the identity-server secret manager.
- `response_type=code` is used; implicit flow is not used.
- S256 PKCE is enabled for every Expo authorization request.
- `state` is generated and checked by the AuthSession request.
- A fresh nonce is generated for every OIDC login.
- The app uses a system browser, not a WebView.
- Refresh tokens are stored only in `expo-secure-store`.
- Production testing uses an Expo development build or standalone build, not only Expo Go.
- iOS and Android app links or custom schemes are tested on physical devices.
- Add Sign in with Apple before iOS release if required by Apple’s current review policies for apps offering third-party login.

## Testing Matrix

Test these cases on both iOS and Android:

- First-time Google login creates one local account.
- Repeated Google login resolves the same account by Google `sub`.
- A Google account with an existing local email is not silently merged.
- User cancels Google login.
- Invalid or expired state is rejected.
- Invalid nonce is rejected.
- PKCE verifier mismatch is rejected.
- Google returns an unverified email.
- Refresh-token rotation succeeds and replaces the stored token.
- Reused refresh token forces a new login.
- Logout removes local credentials and revokes the server token.
- App restart restores a session only from a valid refresh token.
- Redirects work in development builds and production builds using their exact configured URIs.
